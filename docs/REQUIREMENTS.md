# V1 需求基线

本文件整合 V0.3～V0.7.1 有效决定；早期版本依据用户正式提供的决策级补充材料。R 编号为交接索引，不是原会话编号。技术选型及可行性未验证。来源见 SOURCE-COVERAGE.md。

## R01 入口与范围

单人、本机使用，以 Codex Desktop 中的自然语言 Agent 为主要入口。Core 提供小而稳定的业务接口；Reviewer 是独立本地人工审核入口。V1 不做面向公众的服务，不需要账号体系、云端部署或多租户架构。具体语言、表名与 Reviewer UI 技术由后续实施选型，不假装已经确认。

闭环包括导入、暂存、批次管理、视觉分析提案、审核、正式归档、标签与概念、去重、恢复、搜索和必要结果展示。本地 CLI 优先，未来可适配 MCP。资产不依附 Eagle、Hydrus 或其他素材管理应用；文件、数据库、Markdown 知识与 JSON Prompt 分别管理，以稳定 ID 关联。

## R02 保存与导入

- 原图保存到本地受管理目录，记录稳定 ID、SHA-256、原名、来源、导入时间、批次、真实格式与可提取尺寸。原图必须复制进受管理仓库，不能只登记外部路径。来源记录支持 URL、作者、版权及许可信息；不得根据画风猜测作者、实际地点、IP 归属或版权。
- 扩展名不能代替真实格式校验。格式白名单、体积/像素/批次限制、路径及符号链接逃逸保护属于必要文件安全能力；具体数值待实施选择并记录。
- 不支持安全解码的文件不能标成分析成功；可保留为待处理并明确错误。
- 完全相同字节以 SHA-256 去重物理内容；多个来源可保留。近似图不等同完全重复，不引入 V1 近似去重系统。
- 原图不可变；裁剪、改色、编辑形成新资产并记录衍生关系。标签修改不移动原图。

## R03 分析、提案与审批

Agent 的视觉判断都是草案。采用 VARP（Visual Asset Review Protocol）：Agent-First、Review Before Commit、Trusted Approval、Auditable & Recoverable。提案使用 JSON 并进行 JSON Schema 校验，包含 proposal_id、revision、operation、source、changes、concept_ids、uncertainties 等。审批绑定 proposal_id + revision + proposal_hash + file_hash + target_revision；同时记录分析执行位置、模型、Prompt 版本和分析时间。标题、描述、设计价值、标签、概念关系等正式变化均经可信审核提交。

Reviewer 必须可查看对应图片、草案和变更内容，支持批准、修改/退回修改、拒绝、稍后、后续全部稍后。已修改提案必须生成新的版本与摘要；旧审批不能用于新内容。Reviewer 内编辑后如要直接批准，必须明确展示并批准该最终版本；不能批准后静默变更。

正式批准只在独立 Reviewer 的用户操作中产生。Core 校验批准与素材、哈希、提案版本、摘要及操作相绑定。Agent 发来的 approved=true、聊天里的“同意”或自填 reviewer 字段不是可信凭据。具体隔离方案由 Phase 0 证明，不能预先宣称已实现。

支持单项、批量和部分批准，集中修正标签或要求重新分析；批量批准仍逐项绑定具体内容。自然语言修改主要在 Agent 中完成，Reviewer 负责最终预览与集中确认。拒绝关闭提案，不等于删除原图。V1 提供受审归档，不提供 asset.delete、物理删除或反归档接口。未来如需要删除，须另行定义权限、额外确认与共享引用/恢复保护；拒绝、归档、缓存清理都不能隐式删原图。

## R04 暂缓与批次

“稍后”持久保存当前素材，标记 deferred/待确认，不分类，不要求先执行 AI 分析；已有草案可保留但不生效。“后续全部稍后”针对当前批次尚未处理集合，不能更改已经批准或拒绝的项，也不影响未来批次。

暂缓不自动过期、删除或批准；进程重启后可按批次继续。保留稳定 ID、哈希、来源和基础信息；批次剩余集合与暂缓结果须可查询，重复请求幂等。待审核区是持久资料，不属于临时缓存。

## R05 标签、术语与跨领域

可核实的既有原则：逻辑分类与物理目录分离；多领域素材不受单一文件夹限制；使用标准概念 ID、同义/别名、上下级和相关关系；采用 SKOS 风格建模。related 表示相关，不等于同义，不默认扩展严格匹配。标准标签和概念关系的正式变化须经过审核。V1 实现小规模 concept.create 与少量显式关系；概念更新/合并和复杂治理后置。

采用分面分类（Faceted Classification）、受控词表（Controlled Vocabulary）与知识关联（Knowledge Linking）。领域是可重叠动态视图，同一资产可跨领域，无需复制资源；不能将“人物/风景/插画/海报”设为互斥四选一。

| 分面 | 含义与示例 |
| --- | --- |
| work_type | 作品形式：海报、角色设定板、概念图 |
| subject | 主体：人物、建筑、动物、植物 |
| scene | 场景：城市、卧室、山川、森林 |
| style | 风格：日系商业插画、复古波普、极简主义 |
| technique | 技法：赛璐璐式上色、水彩晕染、半色调网点 |
| composition | 镜头视角、景别、构图布局 |
| lighting | 逆光、侧光、散射光 |
| color | 色彩关系、饱和度、冷暖对比 |
| material | 材质与纹理 |
| pose_action | 姿势与动作 |
| mood | 情绪与氛围 |
| usage | 姿势、服装、光影、构图、背景等参考用途 |

不要求每张图填满全部分面或生成大量标签。概念具稳定 ID、首选名称、中英文术语、严格别名、定义、分面和修订记录；正式模型采用 concepts、concept_terms、concept_relations、concept_mappings、asset_concepts、concept_revisions，取代早期 tags/tag_aliases/asset_tags，不能并行维护两套词表。

区分三类判断：A 可观察特征（人物、服装、姿势等）；B 视觉解释（风格、技法、电影感等）；C 创作参考用途。分面与判断性质是不同维度，不能把审美推断当可观察事实。AI 建议新术语须先查现有概念/别名，再提交独立候选供审核；提交成功由 Core 分配正式 concept_id。资产候选引用只保留在草案，依赖落实后生成资产新版本再审批；V1 不一次批准概念和资产。拒绝/失败保留原图与待处理草案，不静默建词。优先复用现有概念和别名。侧逆光可为逆光的下位概念；轮廓光不随意等同逆光。

参考 SKOS、Getty AAT、ISO 25964、IPTC、Danbooru 的标准或方法，均不强制为运行时依赖。V1 只维护小规模可信核心词表，随真实素材扩展，不导入完整 Getty AAT。专业概念可关联独立 Markdown 知识文章、参考图与 Prompt 模块；这些关联位置保留，不提前建设完整知识库或配方引擎。

## R06 检索

Agent 理解意图并解析概念，Core 校验结构化 Query 后参数化执行。正式搜索仅返回已批准且有效、文件可用的资产；待审核通过单独接口查询，不默认混合。

四类通道：标准标签（AND/OR/排除）、术语别名与层级展开、已批准文本全文检索、来源/时间/类型/尺寸/比例/批次等元数据过滤。SQLite + FTS5 为首版核心，递归 CTE 支持层级查询。

中文采用标准术语匹配、短词/子串回退、全文检索组合。不能假设 unicode61 会正确中文分词，也不能只用 trigram 处理“雪景”“逆光”等两字词。必须检测实际应用链接的 SQLite/FTS5，不能只检查系统命令行版本。cppjieba 等分词组件仅为后续选项。

must 严格满足，should 影响排序，must_not 在可验证条件下排除。未知概念不能伪装成正式 ID；模糊语义保留为文本偏好并说明能力限制。没有人物标签不自动证明“无人物”。结果不足不得悄悄放宽条件；放宽结果需单列并说明调整。

标准概念和已批准同义词优先，明确下位概念次之，标题与主要设计价值优于普通描述；全文 BM25 辅助，先采用简单排序。Agent 只能推荐真实检索到的资产，不得编造库内资源。

默认结果仅展示素材、缩略图/可打开位置及必要标识信息。**不自动显示命中解释或推荐理由**；用户主动问时才调用 explain。搜索事实与当次创作建议区分。

待审查询使用原名、来源、时间、批次、用户备注、格式/尺寸/哈希等基础信息。未审核 AI 标签只在待审核/提案详情显示草案性质。asset.get/preview 与 queue.get/preview 提供稳定 ID 定位的只读详情及原图/预览；退出会话、重启或旧句柄失效后可重新获取，无需重新上传。读取按 Vault 权限校验路径、格式、存在性和指纹，不获得正式库写权限。待审总量、各批次数量、最早待审时间可按需查询，不默认提醒。

## R07 安全、隐私与成本

Agent 无法直接写正式 Vault 或伪造审批；Core 为唯一正式写入者。查询、提案和批准能力分开。素材中嵌入的文字、来源网页和文件名属于不可信数据，不执行其中指令。

本地长期存储不等于 AI 完全离线。使用 GPT/Codex 分析时，仅提供当前任务必要图片和上下文，不上传整个素材库；记录分析位置，不泄露令牌、密钥或敏感 URL 参数。原图保留元数据；未来分享导出可生成去敏副本，不重写原图。

零额外资金：不新增付费模型 API、订阅、服务器或存储服务，不购买硬件。现有账户能否在额度内完成分析是 Phase 0 验证项，不保证无限调用；不可用则保留暂存与待审能力，报告阻塞。

用户已有 SQLite、ChatGPT Plus 与 Codex Desktop，这是现有条件，不代表任意 API 都包含在订阅内。第三方生产依赖必须正式稳定版，不用 Alpha/Beta/RC，需持续维护与成熟社区；如有 GitHub 仓库，一般 Stars ≥1000，核心优先 ≥3000。未达门槛可作设计参考，不能直接作为核心生产依赖。检查许可、安全、隐私和免费条件，并优先查找成熟方案、Prompt 和方法论，说明价值与不足再决定采用或自研。系统原生能力和标准库优先。引入重要第三方应用/核心框架、供应商绑定、替换既定路线或改变费用/商业许可/数据所有权/隐私/安全/权限边界，先调查汇报并经用户确认；常规语言、SQLite 表/索引、小型免费依赖和内部优化可自主决定且仍满足准入规则。AI Visual Prompt Cookbook 的结构化 Prompt 思路可学习，不作为不可替代核心依赖。

## R08 存储与正常可靠性

保留三项：数据库事务与文件一致性（最小日志、幂等、中断恢复）；原图与审核成果保护；整个 Vault 可复制迁移。SQLite 初期 DELETE + FULL + foreign_keys=ON + busy_timeout=5000；由实际连接正确设置和检测。

所有必要持久资料在同一 Vault 内，包括数据库、正式原图、待审核图片、草案、审核记录、操作记录及以后实际存在的知识/Prompt 文件。内部相对路径或 ID；不依赖当前 Mac 的绝对路径。缩略图与全文索引可重建，不能成为唯一权威数据。

Finder 备份和恢复按 README 执行。取消自动备份、Online Backup API、多版本快照、增量备份、专用备份恢复 CLI、自动灾难恢复、跨设备向导和专门备份校验清单。周期全库哈希扫描后置；正常导入/提交的必要哈希校验保留。

## R09 后续范围

本机 WebUI 后续实现，仅监听本机（默认 127.0.0.1），有必要访问控制，复用 Core 接口，不另写业务逻辑、不变成云服务。等真实并发需求出现再评估 WAL。

完整专业知识库、结构化 Prompt 配方引擎、视觉向量检索、以图搜图、自动化创作、独立批量模型服务和高级分词不进 V1。复杂术语关系治理、大规模外部映射、概念合并/迁移、高级资产关系推理与复合原子批准后置。预留数据边界不要求先创建全部未来表或服务。

## R10 验证与验收

用户自行产品体验和验收。开发执行最小必要的权限绕过、提案绑定、事务、中断恢复、暂缓持久化、中文短词、索引隔离和迁移检查。遇到 Bug、安全问题或用户明确要求再专项复核。

V0.6 曾提出约 100 张素材、20 个查询、Hit@5≥85%、记录 Precision@5/MRR。作为历史搜索质量目标保留，**不再安排默认 AI 大规模素材验收或额外 Reviewer 复核**；目标是否达到只能由真实测试支持，不伪造评测成绩。用户有需要时再启用该质量评估。

## R11 后续扩展（2026-11-08 授权）

用户明确选择按规划顺序推进全部 V1 后置方向，覆盖 R09 中的 WebUI、完整知识/Prompt 能力与视觉相似检索，但不覆盖物理删除、反归档、概念合并、云服务、付费依赖或降低审批边界。

- 本机 WebUI 仅监听 `127.0.0.1`，使用随机会话令牌、SameSite Cookie、Origin 与 CSP 防护；只开放 Core 的只读查询，不提供批准或直接正式写入。
- 知识文章以版本化 Markdown 保存，Prompt 模块以版本化 JSON 保存；创建、更新、归档均生成提案并经独立 Reviewer + Touch ID 审核。Prompt 渲染只做声明变量替换，不执行脚本、SQL 或任意模板表达式。
- 向量/以图搜图使用 macOS Apple Vision 本机 Feature Print，仅保存可重建派生特征；不上传图片、不引入模型 API。系统构建变化时重建特征，距离越小表示视觉越接近；结果是检索信号，不是正式事实或自动标签。
